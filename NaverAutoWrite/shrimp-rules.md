# AI Agent 프로젝트 표준 (NaverAutoWrite)

> 이 문서는 AI 코딩 에이전트 전용 운영 규칙이다. 일반 개발 지식이나 프로젝트 기능 설명은 포함하지 않는다.
> 프로젝트 배경/아키텍처 설명이 필요하면 `CLAUDE.md`, `doc/PRD.md`, `doc/ROADMAP.md`를 직접 참조하라 — 여기서는 반복하지 않는다.

## 1. 프로젝트 현재 상태 — 반드시 먼저 확인

- 이 저장소에는 **실행 가능한 소스 코드가 존재하지 않는다**. `main.py`, `config.py`, `naver_login.py`, `editor.py`, `md_parser.py`, `image_uploader.py`는 전부 `doc/PRD.md`에만 정의된 **계획된 모듈**이며 실제 파일이 아니다.
- 사용자가 "코드를 수정해줘/버그를 고쳐줘"라고 요청했는데 해당 파일이 없다면, 임의로 존재를 가정하지 말고 먼저 `Glob`/`ls`로 실제 파일 존재 여부를 확인하라.
- 구현에 착수하는 요청을 받으면 `doc/ROADMAP.md`의 **Task 001부터 순서대로** 진행하고, Task 003, 004, 005, 009는 `[Critical]`로 표시되어 있으므로 건너뛰지 마라.

## 2. 요청 처리 필수 절차 (모든 요청에 적용, 예외 없음)

다음 순서를 어기지 마라:

1. 사용자가 입력한 프롬프트 원문을 **수정·요약 없이 그대로** 먼저 출력한다.
2. 요청된 작업을 수행한다.
3. 작업 완료 후 `history.md` 파일 맨 아래에 아래 형식으로 append한다 (기존 내용 삭제 금지):

   ```markdown
   ## [YYYY-MM-DD HH:MM] 요청 요약: <한 줄 요약>

   ### 입력 프롬프트 (원문)
   <원문 그대로>

   ### 처리 결과 요약
   - <핵심 불릿 요약>
   - <변경/생성 파일 경로>
   - <특이사항/리스크/다음 할 일>
   ```

- **하지 말 것**: 코드 전문, 긴 로그 등 중간 산출물을 `history.md`에 기록하는 것.
- **예외**: 순수 확인/대화성 메시지(변경 없는 잡담)는 기록을 생략할 수 있다. 단, 파일 조회·코드 설명처럼 실질적 응답을 제공한 경우는 기록 대상이다.

## 3. 문서 체인 — 파일별 역할과 갱신 순서

| 파일 | 역할 | 갱신 시점 |
|------|------|----------|
| `doc/PRD_PROMPT.md` | PRD 생성용 메타 프롬프트 원본 템플릿 | 요구사항 원문이 바뀔 때만 |
| `doc/PRD.md` | F001~ 기능 ID 단위 실제 명세 | 기능 추가/변경 시 |
| `doc/ROADMAP.md` | PRD 기능 ID → Task 매핑 구현 계획 | Task 완료/신규 Task 추가 시 |
| `history.md` | 모든 요청의 원문+결과 append 로그 | 매 요청 완료 후 (섹션 2 참조) |

- `doc/PRD.md`를 수정하면, 변경된 기능 ID(F00X)가 `doc/ROADMAP.md`의 어느 Task와 연결되는지 반드시 확인하고 **필요 시 해당 Task 항목도 함께 갱신**하라. 한쪽만 고치고 방치하지 마라.
- `doc/PRD.md` 내부에서는 다음 3곳이 항상 상호 참조되어야 한다: **기능 명세 표 → 명령어 구조 → 기능별 상세 명세**. 한 곳에만 존재하는 기능 ID나 모듈은 만들지 마라(정합성 원칙, `.claude/agents/prd-generator.md` 기준).

## 4. 경로 불일치 주의 (실제 버그, 코드 아님)

- 실제 로드맵 파일 경로는 `doc/ROADMAP.md` (**단수 `doc`**)이다.
- `.claude/commands/docs/update-roadmap.md` 커맨드 정의는 `docs/ROADMAP.md`(복수 `docs`)를 전제로 작성되어 있다.
- `/docs:update-roadmap` 커맨드 사용 시 이 경로 불일치로 인해 파일을 못 찾을 수 있으므로, 실행 전 실제 대상 경로가 `doc/ROADMAP.md`임을 명시적으로 확인하고 필요시 직접 그 경로를 지정해 처리하라.

## 5. 서브에이전트 사용 규칙

| 이름 | 상태 | 사용 방법 |
|------|------|----------|
| `prd-validator` | Agent 툴에 정상 등록됨 | `Agent` 툴로 바로 호출 가능 |
| `development-planner` | Agent 툴에 정상 등록됨 | `Agent` 툴로 바로 호출 가능 (ROADMAP.md 생성/갱신용) |
| `prd-generator` | **미등록** — `.claude/agents/prd-generator.md` 파일은 있으나 `Agent` 툴에서 호출 시 "Agent type not found" 오류 발생 | `Agent` 툴로 호출하지 말 것. 대신 이 파일에 정의된 지침(기능 ID 부여, 4단계 정합성 검증 체크리스트, "절대 생성하지 말 것" 목록)을 **직접 읽고 수동으로 따라** PRD를 작성하라 |

- `prd-generator.md`의 "절대 생성하지 말 것" 목록(개발 우선순위, 성능 지표, API 라우트, 인프라, 마일스톤, 개발 단계, 개발 워크플로우, 페르소나, MVP 축소 문구)은 PRD 생성 시 그대로 준수하라. 사용자가 커스텀 목차(마일스톤 등)를 요청하면 두 지침이 상충함을 사용자에게 알리고 우선순위를 확인하라.

## 6. PRD 확정 기술 결정 — 구현 시 뒤집지 말 것

`doc/PRD.md`에 Critical 검증을 거쳐 이미 확정된 사항이다. 구현 코드 작성/리뷰 시 다음을 위반하는 코드를 제안하지 마라:

- **브라우저 스택은 Playwright로 확정**. Selenium/ActionChains 관련 코드나 라이브러리를 제안하지 마라(요구사항 원문에 "ActionChains"라는 표현이 있어도 이는 Playwright의 `keyboard.type`/지연 타이핑으로 치환해야 함).
- 로그인 시 매번 재로그인하지 말고 `context.storage_state()`로 세션을 저장·재사용하는 흐름을 유지하라.
- 고정 `time.sleep()` 사용 금지 — `wait_for_url`/`wait_for_selector` 등 명시적 대기만 사용하라.
- 발행 버튼 등 핵심 조작에 `header__Ceaap` 같은 **해시 클래스 셀렉터를 사용하지 마라**. `get_by_role("button", name="발행")` 등 텍스트/role 기반 셀렉터를 사용하라.
- 발행 처리는 단일 클릭이 아니라 "발행 버튼 → 카테고리/공개설정 패널 → 최종 발행 버튼" **2단계 흐름**으로 구현하라.

## 7. ROADMAP.md 작업 파일 작성 규칙

- 브라우저 인터랙션(로그인/에디터/발행)이 포함된 Task를 작성/수정할 때는 `## 테스트 체크리스트` 섹션을 반드시 포함하라(Playwright E2E 시나리오).
- 완료된 Task는 체크된 박스(`✅`)와 변경 요약을 포함하고, 신규 Task는 빈 박스로 변경 요약 없이 작성하라 — 완료 여부를 섞어서 표기하지 마라.
- `/docs:update-roadmap`을 사용하지 않고 직접 갱신할 경우에도 위 체크 패턴(`- **Task XXX: ...** ✅ - 완료`)과 Phase 전체 완료 시 `### Phase N: 제목 ✅` 규칙을 동일하게 따르라.
